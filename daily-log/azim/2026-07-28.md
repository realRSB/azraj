# Daily Log - 2026-07-28

Owner: Azim

## Summary

Built three prototype user-facing tools on a new branch, hit an SDK tool-use crash while trying to test them live, and cleaned up a live Sendblue webhook hijack caused by local dev testing.

## Work Completed

- Created `feature/efficient-user-tools` off `main` and built three additive dispatcher tools: `set_reminder`/`list_reminders`/`cancel_reminder` (one-time nudges sent directly via iMessage, separate from the cron-based `automations` system), `search_history` (full-text search over raw message content via a new Convex search index), and `get_usage_summary` (surfaces the existing `usageRecords` cost table outside the debug dashboard).
- Attempted to test the new tools live over iMessage; found the installed `@anthropic-ai/claude-agent-sdk` (0.1.77) crashes on any tool call ("tool_use ids must be unique" from the Anthropic API), reproduced with a trivial unrelated script so it's an SDK bug, not caused by the new tools.
- Investigated an SDK version bump to fix the crash; found every version after 0.1.77 hard-requires zod v4, while the whole codebase's tools are written against zod v3 — no compatible SDK version exists without a v3→v4 migration across ~10 files.
- Parked the branch: committed the three tools (`5730965`) for later, left `main` clean, and documented the zod migration as the blocker for picking this back up.
- Discovered `npm run dev` had registered my local ngrok tunnel as a second Sendblue `receive` webhook alongside the live Railway production one, despite `SENDBLUE_AUTO_WEBHOOK=false` in `.env.local`.
- Fixed the webhook hijack by killing ngrok and running `node scripts/sendblue-webhook.mjs https://azraj-production.up.railway.app/sendblue/webhook`, which removed the stale ngrok registration.

## Validation

- Reproduced the SDK crash with a minimal unrelated script to confirm it wasn't caused by the new tools.
- Checked `npm view` peer dependencies across SDK versions 0.1.77 through 0.3.220 to confirm none support zod v3.
- Verified the webhook fix via direct Sendblue API calls (`GET /api/account/webhooks`) before and after — confirmed only Railway remains registered.

## Blockers

- `feature/efficient-user-tools` can't be tested or merged until a zod v3→v4 migration is done (or the SDK ships a zod-v3-compatible patch).
- Root cause of why `SENDBLUE_AUTO_WEBHOOK=false` didn't prevent the ngrok webhook registration is still undiagnosed.

## Next Steps

- When resuming the parked branch, start with the zod v3→v4 migration as its own task (check `server/runtimes/json-schema.ts`'s zod-introspection first, since v4 restructured its internals).
- Before any future `npm run dev` session, check the live Sendblue webhook directly via the API rather than trusting `SENDBLUE_AUTO_WEBHOOK=false` or the local `--check` script alone.
